# Regression ledger

One row per thing that went wrong, or could, in this repository's loop worker (`loop/`, `corpus.yml`,
`loop-fixture.yml`): what it was, the test that pins it, and the commit that fixed it. Each test named here starts
with its row's ID.

- `R-WC-*`: the writecheck loop worker (pull request 61).

| ID | What went wrong | Test | Fix |
|---|---|---|---|
| R-WC-01 | The tools volume held mcp-surface-corpus's `sandbox/` only; its network logger imports `../src/dns.mjs`, so the logger did not start and every unit (the controls first) failed on the first fixture run. The volume now holds `sandbox/` and `src/`, and the driver refuses to pack a volume whose code imports a file that is not in it. | `test/loop.test.mjs`: "R-WC-01: the tools volume carries what its code imports" | b5fbec1 |
| R-WC-02 | The driver called `settingsManifest` from mcp-surface-corpus without loading `src/sandbox-env.mjs`, where it lives: the first sandbox step threw. The driver now loads that module and checks, at load, that every name it uses is exported; a test keeps that list equal to the names the source uses (and checks the exports against a checkout when `MSC_DIR` is set). | `test/loop.test.mjs`: "R-WC-02: every name the driver takes from mcp-surface-corpus is in the list it checks at load" | 5010b05 |
| R-WC-03 | The fixtures ran copies of the dogfood manifests with a new header and `cwd`; the plan hash covers the manifest's bytes, so both plans drifted from the hashes a person accepted and the full write tests did not start. A fixture now runs the dogfood manifest file itself, written two levels below `/work`, with a link that makes its relative `cwd` land on the installed package. | `test/loop.test.mjs`: "R-WC-03: fixtures: valid; each runs its dogfood manifest byte for byte, under the plan hash accepted there" | 1584bb7 |
| R-WC-04 | The output collector walked `/work/out` in path order and stopped at 2,000 entries; tiny-tracker's full run leaves about 2,000 capture files under `full/`, so neither the full run's `results.json` nor the catalog's (`results/` sorts after `full/`) came back, and the summary said "no results folder". The collector now lists everything first and brings the files the summary reads (`results.json`, `catalog.json`, `report.md`, `init-draft.yaml`) before the rest. | `test/loop.test.mjs`: "R-WC-04: the collector brings the files the summary reads first, ahead of thousands of capture files" | cc252b6 |
| R-WC-05 | Security review: the CLI started the server in the same sandbox container, as the same user, with the same `/work`, so a hostile subject could rewrite `/work/out`, write into the CLI's stdout through `/proc/<pid>/fd`, or trace the CLI, and change its own published verdict. Every subject and the forgery control now run split: the server in a sandbox container of its own behind our TCP bridge, with the install volume read-only and no output volume; the CLI in another sandbox container, our helper at the probe address, through our relay. The forgery server now also tries all three, and the control fails as `tampered` unless the CLI's verdict on it is the one its real tool list gives. Only IsoKron's locked fixture servers (full runs need a loopback backend gate and restarts) still share the CLI's container. | `test/loop.test.mjs`: "R-WC-05: the forgery control fails when the verdict was tampered with, not only when text leaked", "R-WC-05: bridge and relay carry a stdio server over TCP, both ways, and the server answers after stdin ends", "R-WC-05: every subject and the forgery control run split; only our locked fixtures share the CLI's container" | 99085e0 |
| R-WC-06 | Security review: the sandbox pin (3b43c19) predated R-SBX-12 (a goto above the firewall jumps). `SANDBOX_REF` is now 97bd96c, and the self test runs through mcp-surface-corpus's reusable `sandbox-conformance.yml` and its `sandbox-guard` action, both at that commit, instead of inline. | `test/loop-workflow.test.mjs`: "corpus.yml: permissions {} on top, timeouts, pinned actions, no secrets, no expressions in run" (and the same for loop-fixture.yml) | 99085e0 |
| R-WC-07 | Security review: kronicle-lite installed unlocked (`npm install` at a version, with install scripts), with three extra install hosts. Both fixtures now install with `npm ci` from a committed lockfile whose entry for the package carries the sha512 integrity pinned in `loop/fixtures.json` (every package from registry.npmjs.org with an integrity), and kronicle-lite's extra hosts are the two its prebuilt binary download uses (github.com, release-assets.githubusercontent.com). Both packages are published by the isokron-ai npm account. | `test/loop.test.mjs`: "R-WC-07: fixtures install from committed lockfiles pinned by integrity, with the narrowest extra install hosts" | 99085e0 |
| R-WC-08 | Security review: teardown checked only for gVisor processes. It now also fails while any host process of the sandbox user (UID 65534) is left. | `test/loop.test.mjs`: "R-WC-08: teardown fails while a process of the sandbox user is left on the host" | 99085e0 |
